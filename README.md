# 🕹️ Agario Clone (Offline Multiplayer)

Java標準ライブラリ（Swing / Graphics2D）のみで実装した、リアルタイム2Dアクションゲーム「Agar.io」のクローンプロジェクトです。
外部のゲームエンジンに頼らず、**「2D描画の高速化」**と**「空間分割アルゴリズムによる衝突判定の軽量化」**を自力で実装し、常時60FPSの快適な動作を実現しました。

## 📝 サービス概要
本家「Agar.io」のゲームシステムをデスクトップアプリとして再現しました。盤面に散らばる餌や自分より小さい細胞を捕食して巨大化を目指します。オンライン通信の代わりに、独自の思考ルーチンを持つBOTを搭載しており、オフラインでも白熱した対戦が可能です。

### 🎮 ゲームモード
- **FFA (Free For All)**: 全員が敵となる個人戦サバイバルモード。
- **Teams (2~4 Teams)**: 2〜4つのチームに分かれ、チーム全体の総面積を競うモード。

### ⌨️ 操作方法
- **マウス移動**: プレイヤー細胞の移動方向の指定
- **`Space` キー**: 自身の細胞を分裂させて前方へジャンプ（素早い移動や捕食に利用）
- **`W` キー**: 自身の質量（餌）を前方に排出（味方への共有や、身軽になるための減量に利用）

## 🎯 開発背景と技術的挑戦
昔、遊んだゲームを再現するために、Javaを使ってゲームをプレイしながら攻略を見ながら設計書を推測

大量のオブジェクトが動的に変化する環境下で、計算量を抑えてシステムを安定させるためのアルゴリズム構築に注力しました。

## 🛠️ 技術スタック
- **言語**: Java ("25.0.2")
- **GUI / 描画**: Java Swing / `java.awt.Graphics2D`

## 📐 技術的なこだわり・最適化ポイント

### 1. 自作Cameraクラスによる視野ズームと高速描画
- **動的ズーム機構**: プレイヤーの質量（細胞のサイズ）が大きくなるにつれて、カメラの視野（Zoom Level）を自動で引き、周囲の状況を広く見渡せる仕様を数学的計算で実装しました。
- **BufferedImageによるダブルバッファリング**: 画面のチラつき（フリッカー）を完全に防ぐため、内部の `BufferedImage` に対して一度全てのオブジェクトを描画し、最終的な1枚の絵を `Graphics2D.drawImage` で一括描画しています。このパイプライン最適化により、描画処理を高速化し、**常時60FPS** を維持しています。

### 2. グリッド空間分割による衝突判定の軽量化（空間インデックス）
- **課題**: 盤面上に数千個の「餌」や「細胞」が存在する場合、全オブジェクト同士の当たり判定（総当たり：O(N²)）を行うと、CPUの処理が追いつかず大幅なFPS低下を招きます。
- **解決策**: 盤面全体を固定の**グリッド空間（2D配列）に分割管理**するアルゴリズムを導入しました。各オブジェクトが所属する周囲のグリッドのみに対象を絞って衝突判定を行うことで、計算量を O(N) に近い形まで削減し、オブジェクトが大量に存在しても処理が重くならないよう軽量化しました。

### 3. 自作BOT（AI）アルゴリズム
- オフラインでもゲームが成立するよう、自作の思考ルーチンを持つBOTを複数配置しています
- 合成ベクトルで実装すればよかったのですが、今回は最も近くの対象にしている
